# Проверка пакета решения

08.11.2026. Проверяется проектирование, не работающее приложение: сервера клиники, PSP и production-нагрузка в рамках учебного проекта не запускались.

## Выполненные проверки

- `openapi-spec-validator 0.9.0`: OpenAPI 3.0.3 и 3.2.0 проходят проверку независимо.
- Примеры каждого ответа проходят JSON Schema-валидацию; контракты совпадают после удаления поля версии OpenAPI.
- Восемь каталогов и README на месте. Автоматическая проверка локальных Markdown-ссылок, XML SVG/Draw.io, уникальности ID и границ редактируемых элементов выполняется `tools/validate.py`.
- Пять PDF отрисованы Poppler и визуально осмотрены: кириллица читается, подписи/стрелки и рамки не обрезаны. Экспорт SVG и PDF векторный; PNG для быстрого просмотра.
- Ручная содержательная проверка: признаки связаны с Jira/SD; сообщение после commit не перепутано с push; нет слепого retry списания; описаны компенсации/UNKNOWN, свежесть полиса и доступ к объектам. Численные настройки помечены проектными.
- Публичный пакет состоит только из решения и средств его воспроизведения. Конспекты, полные задания курса, персональные данные и секреты в него не включены.

## Воспроизведение

Python 3 с пакетами `PyYAML`, `jsonschema`, `openapi-spec-validator`: `python tools/validate.py`.
Для экспорта схем нужны Pillow/ReportLab и Arial (Windows) либо DejaVu Sans (Linux): `python tools/build_diagrams.py`.
Рекомендуется отрисовать PDF через `pdftoppm` и осмотреть изображения после любых изменений layout.

## Ограничения, требующие обследования перед внедрением

1. PSP должен поддерживать однозначный поиск статуса и идемпотентные операции оплаты/возврата. Без этого автоматическая оплата не включается.
2. Из LIS требуется полный индекс/контракт изменений с версиями; из 1С — согласованный экспорт и безопасная семантика свежести покрытия. Их готовность не установлена.
3. Новый Lab Reservation требует утверждения клинических квот и единого владельца календаря для всех каналов. Это предлагаемая новая система, не заявленная готовая возможность LIS.
4. SLO, стоимость, throughput, окна хранения и capacity ещё нужно согласовать и проверить. Расчётные примеры не являются результатами нагрузочных испытаний.
5. Публичность репозитория, состав PR, commit и подтверждение сдачи проверяются на GitHub/платформе после публикации. Этот файл не объявляет сдачу состоявшейся.
